# 参考图反推引擎（Reference Decode）

> 用途：用户给了一张或多张参考图，说「照这个感觉做」「把这图的画风搬过来」「参考这几张 moodboard」「为什么我生成的还是不像」时使用。
>
> 解决一个根本问题：**参考图会连「它当时的状态」一起被抄走**——人物、服装、场地、道具、文字、品牌，全都会跟着进画面。本引擎把这些拆开，只搬「为什么好看」，不搬「图里有什么」。

---

## 一、第一个动作不是分析，是定角色

参考图进来，先确认：**这张图到底管什么？**

不问清，模型会默认「整张图都是风格参考」，然后把人家的人物和场地一起搬过来。

- 用户说了角色 → 以用户为准。
- 用户说了排除 → 按排除收窄（例：「只要光，不要构图」）。
- 用户什么都没说 → **只取最窄的那个角色**，不要默认全都要。

---

## 二、三层拆解（核心）

任何一张参考图的观察结果，必须分三层存放，不许混。

| 层 | 是什么 | 默认怎么处理 |
|---|---|---|
| **A 场景事实** | 这个人是谁、穿什么、在哪、拿什么、画面里有什么字和标志 | **不搬** |
| **B 视觉语法** | 光怎么来、色怎么配、材质怎么反光、边缘怎么收、细节密度多高 | **可搬** |
| **C 混合决策** | 构图、机位、主体占多大、有没有遮挡、留白多少、光从哪边来 | **看新场子需不需要** |

判断口诀：**A 是「图里有什么」，B 是「为什么好看」，C 是「怎么摆」。**

### 冲突时谁优先

```
用户明确指定的  >  参考图带来的  >  系统默认补的
```

C 层特别容易出事：参考图是「小人站在巨大空间里」，而用户要的是近景特写。**这时候放开主体占比，保留能兼容的光、色、材质、边缘。** 构图不会因为「参考图里最有特色」就赢。

---

## 三、角色表：一张图管一件事

| 角色 | 管什么 | 不自动管什么 |
|---|---|---|
| 画风 / 视觉语法 | 配色关系、曝光倾向、光线行为、材质处理、细节密度 | 不自动管构图、机位 |
| 成品媒介 | 这是照片、插画、剪贴、印刷品、风格化 3D | 不自动管主体、剧情 |
| 角色长相 | 脸型五官、体型、年龄感 | 不管服装和姿势（除非一并指定） |
| 服装 | 版型、层数、材质、配饰 | 不管脸 |
| 道具 | 具体物件、车型、产品 | 不管场景 |
| 地点 | 场地身份、建筑结构、地理关系 | 不管人物 |
| 构图 | 视觉中心、主体大小、留白、层次 | 不管光 |
| 机位 | 视点位置、高度、距离、透视、画框边界 | 不管构图平衡 |
| 光线 | 光源方向、类型、对比、衰减、高光与暗部行为 | 不管色彩倾向 |
| 色彩 | 色相关系、饱和度结构、脏色、点缀色 | 不管光源 |
| 材质 | 粗糙度、光泽、透光、磨损、表面反应 | 不管颜色 |
| 质感 / 成像 | 颗粒、模糊、光晕、压缩、锐度、运动残留 | 不管画面内容 |
| 空间结构 | 前中后景关系、通道、门槛、环境占比 | 不管人物动作 |
| 氛围 | 只取能说清成因的那部分，不取形容词 | 不单独搬「高级感」 |

**一张图尽量只给一个角色。** 只有用户明确说「这张图同时管 A 和 B」时才合并。

---

## 四、逐维观察清单

只分析**能解释这张图为什么好看**的维度，不要为了填表而填表。

- **媒介判断**：这是拍摄的，还是画出来的、印出来的、渲染出来的？混合媒介就写清楚主次。
- **构图**：主体位置与占比、留白、对称与否、视觉中心、前后层次、边缘张力、裁切、遮挡。
- **机位 / 视点**：从哪个位置看、多高、多远、透视强弱、画框切在哪。
- **光与明暗**：光源从哪来、什么性质、对比多强、暗部有没有被保护、高光到哪停。
- **曝光**：高光过渡、暗部密度、中间调、整体偏亮还是偏暗、有没有刻意欠曝或过曝。
- **色彩**：主色与辅助色关系、饱和度结构、冷暖平衡、阴影里是什么色、高光里是什么色、有没有串色。
- **材质**：粗糙度、光泽、透光、磨损、纹理尺度、表面反应、材质之间的对比。
- **空间**：层次、纵深、建筑与人的关系、环境占比、有没有「框中框」、门槛与通道。
- **人物 / 调度**：是摆拍还是被抓到的、视线朝哪、身体朝哪、手在做什么、和环境什么关系。
- **成像特征**：颗粒、模糊、光晕、压缩、锐度、运动残留、刻意的瑕疵。
- **美术倾向**：杂志感、纪实感、观察式、图形化、极简、密集、装饰、怀旧……选最像的那一两个。
- **它刻意没做什么**：这张图避开了哪些常见套路（人人都在打的轮廓光、hdr 感、青橙调、过度锐化、商业磨皮）。

> 「刻意没做什么」这一项只能从**当前这张参考图**里找，不要贴一份通用负面词上去。

---

## 五、压成 5–8 条核心规则

完整分析不是给模型看的。真正进入提示词的，是从分析里压出的 **5–8 条规则**。

一条合格的核心规则必须：
- 说的是**能看见的关系或行为**，不是形容词；
- 会实际影响构图、光、色、材质、空间、调度或成像；
- **换了主体和故事之后仍然有用**；
- 带条件就说条件，不要写成绝对真理。

### 合格写法（照这个感觉写）

- 环境占的画面比重比人更大；除非用户明确要人像，否则人始终是被环境包住的一小块。
- 主光只来自有出处的门窗、路灯、招牌或天光；不加没有来源的轮廓光。
- 高光接近溢出但仍保住色彩，暗部保持密度，不把整张图提亮成 hdr。
- 人物处于「正在发生」的动作里，不做正面完成式摆拍。
- 用真实的前景建筑或物件制造遮挡，把「观察距离」做出来。

### 不合格写法（一律不要）

`电影感`　`高级灰`　`氛围感`　`光影迷人`　`质感很棒`　`大片感`　`有故事感`

这些词没有一条能指导模型做决定。

## 六、迁移范围：哪些能搬

### 强继承（观察到就可搬）

色彩结构、光线行为、曝光行为、材质处理、质感与成像特征、细节密度、媒介本身。

### 条件继承（要看新场子）

构图、机位、主体占比、留白、遮挡、空间层次、调度关系、焦段行为、对称与否、光的方向。

每条都要标一句状态：

| 状态 | 意思 |
|---|---|
| **保留** | 用户明确要，且跟新场子不冲突 |
| **改造** | 保留关系，改掉具体数值（例：还是「人小环境大」，但换一个场地） |
| **放弃** | 新故事的逻辑或物理条件不允许 |

### 不搬（除非用户单独指派）

人物身份、具体服装、具体地点、具体道具、画面里的文字、品牌标志、具体建筑、具体故事情节、只属于原图的杂物。

## 七、多张参考图怎么办

先选模式，**不要把所有图平均成一种风格**。

### 共识型（moodboard）

用户说「参考这几张的感觉」，没分工时用。

1. 每张图独立拆三层；
2. 找**反复出现的关系**，不是反复出现的形容词；
3. 分成「稳定规则」和「可变项」；
4. **矛盾不要平均**——标成可变、有条件、或未解决。

### 分工型

用户说「图一管颜色、图二管构图、图三管人物、图四管材质」时用。

1. 先把分工记下来，再分析；
2. 每张只取它被分配的那个维度；
3. 同一维度被两张图占了 → 按用户给的优先级；
4. 人物、服装、道具、地点这类身份角色，**不要和画风混在一起**。

### 冲突处理顺序

```
新场子的硬事实  >  用户明确的分工与优先级  >  用户明确的排除
>  已锁定的连续性设定  >  用户认可过的风格卡  >  推断出来的观察
```

两条明确指令真的打架、且会影响成片 → 直接说清冲突，问一个问题，不要自己折中。

## 八、接到 AAA 流水线（不许破坏现有契约）

反推结果必须落到对应的站，不能到处重复注入，否则会互相稀释。

| 站 | 接什么 | 怎么接 |
|---|---|---|
| 第2站 问风格 | B 层视觉语法 | 写进 **LOOK 卡**，一次性定进【全局质量提示词】。**不许在每一镜里重复写视觉语法** |
| 第3站 建资产 | 角色 / 服装 / 道具 / 地点类参考 | 走 `asset-templates.md`，把参考图作为「以参考图为准」的输入 |
| 第4站 拆单帧 | C 层构图、机位、光的方向 | 只落到九层里对应的那一层；**用户自己的构图需求优先于参考图** |
| 第5站 生视频 | 素材职责 | 仍走 SKILL.md 5.2 的写法，本引擎不重复定义 |
| 第5.5站 诊断 | 结果与参考不一致 | 走下面第九节 |

### 非摄影媒介的分支闸门

如果参考图本身是插画、剪贴、印刷品、风格化 3D、低多边形：

- **只在用户明确要这种风格时启用**；
- 启用后，第4站九层里的 ④摄影机 改为写「视点 + 明暗结构 + 边缘处理 + 表面反应 + 笔触或渲染逻辑」；
- 没被指派的媒介，**不要**自动把参考图的媒介搬过来；
- 默认仍然是 AAA 主线的写实 / 电影方向。

> 这不是推翻九层，而是给非摄影题材留一个明确入口。

## 九、生成结果不像参考怎么办

先分清两类差异，**不要一上来就重写整段提示词**。

### 合理改写（不要修）

新故事的空间、动作、物理逻辑要求的调整。用户要近景，参考图是小人远景——这是对的，不是漂移。

### 真漂移（才修）

- 媒介变了：纸面上的平涂边缘变成了照片皮肤，或哑光 3D 变成了亮面渲染；
- 核心规则丢了：主光变成无来源的装饰光、暗部被整体提亮；
- 强继承丢了：色彩结构、曝光行为整体换了一套；
- **原图内容漏进来了**：参考图里的路人、道具、招牌出现在新画面里。

### 修法

1. 最多挑 **3 个主因**，挑最有证据的；
2. 输出格式：

```
【只改】
（最小范围的具体修正）

【保持原样】
（已经对了的事实与规则）

【目标模型改图指令】
（该模型能听懂的改法）
```

3. 只有结构（故事、调度、空间、机位）真的错了，才回第4站重建；光色材质漂了不要重建整个场面。

## 十、反推完成自检

- [ ] 每张图都分配了角色，没有一律当"风格参考"
- [ ] A / B / C 三层分开存放，没有把图里的人和物写成风格
- [ ] 核心规则压到了 5–8 条，每条都是可执行的关系描述
- [ ] 核心规则里没有 `电影感`、`高级灰`、`氛围感` 这类词
- [ ] 条件继承项都标了「保留 / 改造 / 放弃」
- [ ] 「不搬」清单是照着这张图写的，不是贴通用负面词
- [ ] 多图时没有把矛盾平均掉
- [ ] 视觉语法只在第2站注入一次，没有在每一镜重复
- [ ] 非摄影媒介只用了一次分支闸门，没有顺手否定 AAA 主线的写实方向

## 十一、常见错法

| 错法 | 后果 | 正确做法 |
|---|---|---|
| 把参考图整张当风格 | 人物、场地、道具一起被抄进新片 | 先定角色 |
| 用形容词总结风格 | 模型无从执行 | 换成能看见的关系 |
| 把完整分析塞进提示词 | 提示词过长、重点被稀释 | 只交 5–8 条核心规则 |
| 每镜都重写一遍画风 | 与全局质量提示词互相稀释 | 第2站注入一次 |
| 参考图构图好看就照搬 | 新故事讲不通 | 按「保留 / 改造 / 放弃」判定 |
| 结果一不像就整段重写 | 丢掉本来对的部分 | 先分「合理改写」和「真漂移」 |
| 把所有参考图平均成一种风格 | 得到一张谁也不像的图 | 共识型找交集，分工型按角色 |
