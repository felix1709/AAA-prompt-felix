# 结果修复契约（Result Repair）

> 用途：用户拿回一张生成结果，说「不对」「不像我要的」「怎么改」时使用。
>
> 只处理**单帧 / 生图结果**。视频结果的诊断走第5.5站；参考图风格漂移走 `reference-decode.md` 第九节。

---

## 一、第 0 步：先判断结构对不对

**不要一上来就改形容词。** 先问一句：

> 问题出在「画面结构」，还是出在「光色材质」？

| 判断 | 现象 | 走哪条 |
|---|---|---|
| **结构对** | 故事瞬间对、人站位对、空间对、机位对，只是不好看 | 走 A：外科修复 |
| **结构错** | 故事瞬间错、视觉中心错、调度错、空间关系错、机位不可能 | 走 B：重建 |

**结构错了还堆形容词，只会越改越糊。**

---

## 二、A 路线：外科修复

只动需要动的地方，其余全部保护起来。

```
【只改】
（最小范围、可观察的具体修正）

【保持原样】
（已经对的事实：长相、服装、场景、动作、机位、光、空间、其他物件）

【目标模型的改图指令】
（按该模型支持的写法，见 model-adapters.md）
```

### 三条纪律

1. **一次只改一个有意义的变量。** 用户一口气提了三个不相干的问题 → 分成三轮，或者先问哪一个是主要的。
2. **上一轮已接受的成品要作为下一轮的输入**，并重复一遍保护规则。多轮编辑会累积漂移。
3. **不承诺像素级一致。** 说"保持"是可以的，说"绝对不变"不诚实。

### 例

```
【只改】
把左脸从全亮压到半明，让台灯成为画面里唯一暖光源

【保持原样】
人物的脸、发型、衣服、坐姿，窗框位置，桌面道具，机位与画幅

【GPT Image 2.5 改图指令】
Change only the lighting on the left side of the face... preserve identity, pose, wardrobe, window position, props, framing.
```

---

## 三、B 路线：重建

结构真的错了时：

1. 回到**场景本身**（故事瞬间 / 视觉中心 / 调度 / 空间 / 机位），重新定；
2. 说清哪些成功的事实仍然锁住（长相、服装、地点、时间）；
3. 从第4站重新走九层；
4. **不要**在旧提示词后面继续加修正句。

## 四、主因清单（挑最多 3 个，挑最有证据的）

### 内容层

| 主因 | 长什么样 |
|---|---|
| 故事瞬间错 | 抓了一个没有戏的瞬间，或者堆了两个不该同时发生的状态 |
| 调度错 | 人物姿势不符合剧情，或前后镜接不上 |
| 空间错 | 前中后景关系不通，人站不到那个位置 |
| 道具状态错 | 东西在错的手上、错的朝向、错的损坏程度 |
| 连续性错 | 衣服干了、道具跑位、光换了方向（→ `continuity-bible.md`） |

### 视觉层

| 主因 | 长什么样 |
|---|---|
| 机位错 | 视点不可能存在，或高度距离不对 |
| 构图错 | 视觉中心不在该在的地方，主体占比不对 |
| 光错 | 光源没有出处、方向不对、暗部被提亮 |
| 曝光错 | 高光死白、暗部死黑、整体提亮成 HDR |
| 色彩错 | 色彩关系不是从光源来的，是全局预设 |
| 材质错 | 表面都一个亮度、都光滑、都没有磨损 |
| 质感错 | 全图等清晰，没有选择性清晰 |
| **商业感 / 广告感** | ⚠️ 这是**症状不是原因**，见下 |

### 模型层

| 主因 | 长什么样 |
|---|---|
| 语法错 | 把 MJ 的参数写进了 GPT Image，或反过来 |
| 参考角色错 | 参考图被当成了它不该管的东西 |
| 能力越界 | 要求了该前端不支持的编辑控制 |

### 特别提醒：「商业感」不是一个原因

用户说"太像广告"，不要直接回"降低商业感"——模型听不懂。

往下拆，通常是这四个具体决定造成的：

1. 人物在**摆拍**，不在做事；
2. 主体**居中且占比过大**；
3. 每处高光都**一样漂亮**，没有暗区；
4. 机位**居高临下**，什么都能看见。

**改这四个，比加任何负面词都有效。**

## 五、和 AAA 现有机制怎么分工

| 已有机制 | 管什么 | 什么时候用 |
|---|---|---|
| **第5.5站 生成后诊断** | **视频**结果：Prompt / 参考素材 / 运行参数 / 模型随机性 / 模型能力 | 拿到成片后 |
| **`result-repair.md`（本文件）** | **单帧 / 生图**结果的结构判断与外科修复 | 拿到一张图后 |
| **`reference-decode.md` 第九节** | 结果和**参考图**不一致：合理改写 vs 真漂移 | 用户拿参考图对比时 |
| **`continuity-bible.md`** | 多镜之间的状态漂移 | 系列项目 |

> 四者不重叠：**视频归第5.5站，单图归本文件，对参考图归反推，跨镜归连续性。**

## 六、常见错法

| 错法 | 后果 |
|---|---|
| 用形容词修结构问题 | 越改越远，最后只能重来 |
| 一次改五个地方 | 不知道哪个起作用，也没法回退 |
| 把"商业感"当原因 | 改不动，因为没有对应的操作 |
| 结构错了还做局部编辑 | 局部再准也救不回来 |
| 每轮都重写整段提示词 | 丢掉上一轮已经对的部分 |
| 承诺"完全不变" | 做不到，而且会误导用户预期 |

## 七、自检

- [ ] 先判断了结构对错，再决定改法
- [ ] 主因不超过 3 个，且每个都有画面证据
- [ ] 「商业感」已经拆成了具体的构图 / 光 / 姿势决定
- [ ] 【只改】和【保持原样】都写成了可观察的表述
- [ ] 改图指令符合目标模型实际支持的写法
- [ ] 没有承诺像素级一致
- [ ] 结构错时走了重建，没有在旧提示词上叠修正
