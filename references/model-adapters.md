# 模型适配层

> 用途：第5站生视频 / 第6站特殊分支时，把统一构思转成各目标模型要求的格式。
> 原则：主线全中文；MiniMax H3、Midjourney、FLUX 输出英文；Seedance / GPT Image / Seedream / Nano Banana 可中可英。
> **Seedance 2.5 的完整规范见 `seedance25-playbook.md`（权威）**，本节只列格式要点。
> 生图适配器共 5 个：Midjourney V8.2 / FLUX·SD / GPT Image 2.5 / Seedream 5.0 Pro / Nano Banana 家族。

---

## 1. Seedance 2.5（视频 · 首选）

- **语言**：中文（或英文）
- **能力**：单段 **30 秒直出**；单次 ≤ 50 份参考素材；支持 生成 / 编辑 / 延长 / 多语言
- **格式**：按任务选模板（全文见 `seedance25-playbook.md` 第八节）
  - **基础生成**（4 行）：`主体+场景+动作 / 视觉风格 / 镜头 / 声音`
  - **带参考素材**：`【生成目标】【参考素材职责】【未采用素材】【主体与关系】【事件脚本】【保持一致】`
  - **多素材分组**：`【人物】【道具】【场景】【动作与声音】`
  - **视频编辑**：`【编辑目标】【原视频职责】【目标素材职责】【编辑对象与范围】【时间线继承】` + 范围闭环兜底句（必写）
  - **视频延长**：向后 / 向前 + 单一实例拓扑要求
  - **关键帧**：`@图片N作为首帧。` / `@图片N作为尾帧。`（必须独立成句）
  - **白模**：粗粒度（结构/路径/运镜）/ 细粒度（换形象材质）
  - **宫格分镜**：读取顺序 + 逐镜描述
- **时间组织**：默认**阶段式**（`【阶段一】开始时…主要事件…结束时…`）；秒数仅在用户明确要求时用
- **符号系统**：音乐 `()` ｜ 音效 `<>` ｜ 台词 `{}` ｜ 字幕 `【】`
- **参数分离**：比例 / 时长 / 分辨率**不进 Prompt**，由页面或接口设置
- **输出合同**：默认只输出 Prompt 正文，无 Markdown 标题、代码围栏或外层包装
- **禁忌**：无精确物理数值；不自动加通用负向包（无噪点/无水印/HDR）；不用范围句做素材映射；不做同义改写式的"伪优化"

## 2. Seedance 2.0（视频）

- **语言**：中文
- **格式**：六段式
  1. 视听限制（无背景音乐、纯现场环境音、禁止字幕水印）
  2. 语言台词
  3. 运镜手法（镜头是否移动/路径/与角色关系）
  4. 风格色调与光景
  5. 角色与场景设定
  6. 时间轴详细叙事（按秒拆：景别/动作/神态/台词/声音）
- **硬上限**：全文 ≤ 1900 字（含标点），超限按「时间轴 → 环境音 → 角色次要细节 → 台词 → 秒段合并」顺序压缩
- **禁忌**：无精确物理数值；距离/高度用身体参照（一臂距离/与眼平齐）、画面比例（人物占画面几成）替代

---

## 3. Seedance 5.0（视频 / 出图）

- **语言**：中文或英文均可
- **视频**：沿用 Seedance 2.0 的六段式
- **出图参数**：
  - `size`：人像 `1024x1536` / 场景横构 `1536x1024` / 单体特写方形 `1024x1024`
  - `quality`：`high`
- 出图前做三项确认：四锚点/质量词齐全、无冲突硬光词、尺寸匹配主体

---

## 4. MiniMax H3（视频）

- **语言**：英文
- **模式**：
  - Ref2VA —— 参考图只提供风格（默认）
  - I2VA —— 首帧对齐；L2VA —— 尾帧对齐；FL2VA —— 首尾帧对齐
- **字段**（拼写严格）：
  `subject_definitions` + `summary` + `retention_analysis` + `detailed_description` + `overall_soundscape` + `non_diegetic_music`
- **总字符** ≤ 10000；分配：detailed_description 主配 4000-5000，音轨/音乐各 800-1000
- **每镜** 50-200 字符，多数镜头一句话，仅关键镜头两句
- **镜头数**：15s → 18-25 镜
- **音轨**：按阶段块写（Hook / Build / Climax / Freeze），不按逐镜时间戳
- 对话格式 `(S1) says: <d>[English] Text.</d>`；屏上文字用英文双引号

## 5. Midjourney V8.2（生图）

> 版本基线核对日期 2026-09。参数以官方文档为准，不要凭印象编。

- **语言**：英文描述 + 参数
- **版本**：不写版本 = **V8.2**。不要默认写 `--v 6` / V7。只有用户要求锁定版本、或要一段能直接进 Discord 的完稿时才显式写 `--v 8.2`；用户明确要 V6/V6.1/V7 时当旧版处理，先核对那个版本的参数兼容性
- **写法顺序**：主体与当前动作 → 与前中后景、视觉中心的关系 → 机位的物理位置、高度、距离、主体占比 → 有源光与明暗关系、材质反应 → 参数全部放最后
- **不要**把它改写成 `cinematic, masterpiece, photorealistic, 8K, ultra detailed, award winning` 这类关键词串
- **参考图角色**（一图一角色）：

| 类型 | 管什么 | 不要声称 |
|---|---|---|
| Image Prompt | 影响内容、构图、色彩关系 | 精确复制 |
| Style Reference | 迁移风格、配色、质感、媒介 | 锁定人物身份 |
| Edit Model Reference | 融合/编辑供图的人物、物件、场景，最多四张 | 像素级一致 |
| Moodboard / Personalization | 套用用户的整体审美档案 | 锁场景事实或构图 |

- **Imagine vs Edit Model**：要保形、改透视、局部重绘、扩画幅、多图重组 → 走 **Edit Model**（它已取代旧的 Omni Reference / Character Reference / 独立 Retexture 流程）。不要把这些需求硬塞进普通 Imagine
- **`--raw`**：是控制项，不是电影感后缀。要强提示词服从时考虑加，要探索性时不要加
- **`--stylize`**：低值=严格执行，中值=电影化诠释，高值=明显倾向 MJ 的审美并接受语义漂移。**不要默认塞一个数值**
- **支持的参数**：`--ar` `--raw` `--s` `--weird` `--seed` `--sref` `--iw` `--no` `--profile` `--hd`/`--sd` `--edit` `--v`
- **不支持**（不要用）：`--quality`/`--q`、`--draft`、`--turbo`、`--niji`、`--oref`
- **比例**：按真实比例写 `--ar 2:3`，不要自动换成 `9:16`。SD 上限 14:1，HD 上限 4:1；超出就说明不兼容，不要偷偷改比例
- **排除**：先用正向设计解决限制。`--no` 只放短的、具体的、能干净排除的词；不要把一大段负面段落塞进去，也不要放多词短语（拆开后会自相矛盾）
- **种子**：`--seed` 只控制初始噪声，**不是**角色 ID、风格 ID 或连续性系统
- **不许编**：图片 URL、`--sref` 编号、`--iw`、`--sw`、seed、profile、权重范围

**常见崩**：旧式关键词堆砌；自动加 `--raw`；乱填 `--s`；机械地写 `--v 8.2`；丢了机位与光的关系；擅自改比例；把 Style Reference 当身份锁；拿 seed 当连续性；伪造参考数据；该用 Edit Model 却走了 Imagine。

## 6. FLUX / Stable Diffusion（生图）

- **语言**：英文
- **格式**：正向 + 负向，权重写法 `(35mm film:1.1)`
- 正向：风格加权关键词在前，场景/角色/道具/构图在后
- 负向：digital noise, CGI, 3d render, sharp studio light, harsh flash, oversaturated, plastic skin, watermark, text, logo, extra limbs, deformed, low quality, jpeg artifacts
- 排除词按场景选，不要每次贴整份（选法见 `anti-ai-look.md`）

---

## 7. GPT Image 2.5（生图）

> 基线：ChatGPT Images 2.5。GPT Image 2 / `gpt-image-2` 走兼容模式，旧提示词**先在 2.5 上原样跑一遍**，只修实测失败的地方，不要因为版本号变了就重写。

- **语言**：中文或英文的完整句子，按功能分段。**不要关键词堆砌**
- **结构**：
  1. 任务与场景事实
  2. 故事节拍与当前动作
  3. 调度、物件交互、物理空间
  4. 视点与取景（摄影媒介写机位/距离；非摄影媒介写视点与版面）
  5. 明暗、色彩、材质反应
  6. 边缘、笔触、纸面、渲染或成像特征 + 画幅意图
  7. 整合后的限制与保持规则
- **不要**新加 `masterpiece` `8K` `award-winning` `hyper detailed` 这类质量套话
- **编辑**：写清【只改】和【保持原样】，用可观察的词。**多轮编辑一次只改一个有意义的变量**，并把上一张已接受的成品作为下一轮输入。多轮会累积漂移，**不要承诺像素级一致**
- **参考图**：只写 brief 级的角色分工（长相 / 服装 / 物件 / 地点 / 构图 / 材质 / 光），不要发明附件字段或权重
- **排除**：融进对应的那句话里（例：「车库保持普通当代感，不要赛博朋克打光」），不要指望独立的负向字段
- **常见崩**：过长且重复；把每处表面都美化；参考图角色没分配导致身份或版式漂移

## 8. Seedream 5.0 Pro（生图）

> 注意：**Seedream 是生图，Seedance 是生视频**，两个产品，命名别混。

- **强项**：空间关系表达、带标注的局部编辑、多图融合、多语言文字排版
- **写法**：写一份**空间制作简报**——显式写出相对位置、遮挡关系、尺度、前中后景、视觉中心。中度细节最好，既不要关键词碎片，也不要反复啰嗦
- **结构**：画面意图与固定事实 → 故事节拍与调度 → 空间布局与视觉中心（用具体的相对位置）→ 视点与层次 → 有源光、曝光、材质反应 → 文字或参考图角色 → 明确的排除与保持规则
- **参考图**：指定底图与每张辅助图各管什么（版面 / 长相 / 服装 / 物件 / 材质 / 光）
- **编辑**：只有在当前界面真的提供点、框、蒙版、标注时才按区域写；没有就写一般编辑指令，**不要声称能做到像素级精确**
- **参数**：不编 API 字段、坐标语法、标注格式、强度、参考图数量上限、分辨率
- **常见崩**：把一段散文请求当成有区域工具来用；一段提示词里同时塞电影场景和信息图；参考图角色互相冲突；多余的商业抛光

---

## 9. Nano Banana 家族（生图）

> 别把整个家族当成一套能力。Lite / 2 / Pro / 旧版各不一样，**用用户实际点名的那个成员**。

- **语言**：直接的自然语言指令。先说想要什么，再说场景关系，最后说保持/改动
- **结构**：生成或编辑任务 → 场景、故事节拍、动作 → 人物调度与参考图角色 → 物理空间、视点、视觉中心 → 有源光、色彩、材质、成像 → 需要的文字与版式 → 保持/改动约束
- **编辑**：用具体画面语言写「只改什么」「保持什么不变」；新内容要继承底图透视、光源、颗粒/噪声特征与材质反应
- **参考图**：一图一角色，角色重叠时说明优先级。**多参考能力因成员而异**，不要假设最快的那个擅长复杂参考组或长链编辑
- **参数**：不编模型 ID、API 字段、参考图数量、输出分辨率
- **常见崩**：把各成员当等价；preserve 写得含糊；长链连续编辑累积漂移；参考图角色没分配

## 附：模型选择速查

| 要做的事 | 首选 | 备注 |
|---|---|---|
| 15–30 秒成片、要参考素材 | **Seedance 2.5** | 最强，支持素材职责与编辑延长 |
| 稳、字数为王的老流程 | Seedance 2.0 | 1900 字六段式 |
| 既要视频又要图 | Seedance 5.0 | 带 size/quality |
| 高速分镜、节奏强的片 | MiniMax H3 | 英文，18–25 镜 |
| 单张生图（艺术向、要参数控制） | Midjourney V8.2 | 英文 + 参数，别写 `--v 6` |
| 单张生图（自然语言、要编辑保形） | GPT Image 2.5 | 完整句子，【只改】/【保持原样】 |
| 单张生图（空间关系复杂、要标注局部改） | Seedream 5.0 Pro | 空间制作简报 |
| 单张生图（对话式快速迭代、多参考） | Nano Banana 家族 | 先确认是哪个成员 |
| 单张生图（要负向词、要精细权重） | FLUX / SD | 英文 + 正负向 + 权重 |
