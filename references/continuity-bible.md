# 连续性圣经（Continuity Bible）

> 用途：一条片子超过 3 镜、或者有状态变化（衣服湿了、妆花了、道具换手、时间推进、地点转移）时使用。
>
> AAA 现在的「承接上文，从 XX 姿态转为 XX」只管**镜与镜之间的动作衔接**。
> 这份文件管的是**全片的事实锁定**——人物长相、服装状态、道具归属、空间拓扑、光源位置、时间推进。

---

## 一、先分清两件事

| | 管什么 | 谁负责 |
|---|---|---|
| **资产** | 这个人**长什么样**、这地方**什么结构** | 第3站 `asset-templates.md` |
| **连续性** | 这个人**现在什么状态**、这地方**此刻什么情况** | 本文件 |

资产是静态的基准；连续性是**会随着剧情变化的状态**。

举例：角色的三视图资产永远不变，但「第5镜开始外套湿透、右袖撕裂」是连续性。

---

## 二、什么时候必须建

满足任意两条就该建：

- 镜头数 ≥ 4
- 同一人物出现在 3 镜以上
- 有服装 / 妆容 / 伤口 / 湿度的变化
- 有道具在人物之间转手
- 故事跨时间（同一天不同时段，或跨天）
- 有地点转移，且观众需要理解空间关系
- 有反转、揭示、时间倒叙

**短于 3 镜的单场戏不用建**，直接靠资产 + 承接上文。

---

## 三、锁定表：八个字段

建表时只填**会变化的**和**必须一致的**，不要什么都写。

### 1. 人物身份

| 记什么 | 不用记 |
|---|---|
| 脸型五官、年龄感、体型、发型、发色、有无痣/疤、惯用手 | 临时表情、临时姿势 |

### 2. 服装

版型、层数、材质、配饰、鞋。**状态按时间顺序追**：干 → 淋湿 → 半干；整洁 → 起皱 → 撕裂。

### 3. 妆容与皮肤

底妆、唇色、发型定型程度、汗、油光、灰尘、血迹。**不要每镜都重画一张新脸。**

### 4. 道具

物件身份、在哪只手上、朝向、位置、有没有损坏、里面装了什么。

> 道具不能无缘无故换手、换位置、复位。每次移动都要在对应的那一镜里写出来。

### 5. 地点拓扑

入口、出口、柱子、窗户、楼梯、道路、家具、固定地标、机位能站的位置。

**左右和远近关系要锁住**，除非镜头明确写清越过了轴线。

### 6. 光线

固定的光源有哪些、时间怎么推进、色温怎么变、哪个光源会灭、哪个会亮、哪些暗部要保护。

> 不要每一镜都为了好看重新布一次光。

### 7. 机位语法

常用视点位置、主体占比范围、焦段行为、运动方式、遮挡逻辑、轴线规则、禁止的"英雄式"构图。

单镜可以在这个语法内变化，但**要有理由**。

### 8. 叙事状态

每一镜之后的当前状态：

```
当前地点 / 当前时间 / 各人物位置 / 服装状态 / 道具归属 / 天气 / 尚未完成的动作
```

## 四、Base Lock + Shot Delta（写法）

不要每一镜都从头描述整个场面——既累又会漂。

```
BASE LOCK（全片不变的部分）
  + SHOT DELTA（这一镜相对上一镜变了什么）
  = 这一镜的单帧提示词
```

### 写法示例

```
【BASE LOCK】
- 人物：短发、左眉尾有一道浅疤、惯用右手
- 服装：米白衬衫 + 深灰长裤；第3镜起右袖淋湿
- 地点：旧公寓客厅，沙发靠东墙，窗在西侧
- 光：唯一主光是西窗落日，随时间变暖变低
- 机位语法：视线高度，主体占画面 25–40%，不做居中对称

【SHOT 05 DELTA】
- 时间：落日更低，窗光已斜到沙发扶手
- 人物：从站姿转为坐在沙发左端，右手仍拿着信
- 服装：右袖全湿，左肩开始洇湿
- 道具：信在右手，未拆封
```

### 三条纪律

1. Shot Delta **只写变化**，不要把 Base Lock 再抄一遍。
2. 变化要有**物理后果**：手拿了东西 → 那只手就不能再做别的；湿了 → 后面的镜头必须还是湿的。
3. Shot Delta **不许偷偷改 Base Lock**。真需要改（比如角色必须换装），就明说这是剧情决定，然后更新 Base Lock。

## 五、和 AAA 现有机制怎么配合

| 已有机制 | 关系 |
|---|---|
| `asset-templates.md` 资产 | 连续性的**长相与结构来源**。人物身份直接从三视图资产取，不重复描述 |
| 「承接上文，从 XX 转为 XX」 | 连续性在**动作层**的落地。Base Lock 管状态，这句管姿态接续 |
| `stage-split.md` | 决定某个属性属于单帧还是视频；连续性只管**值**，不管写在哪一站 |
| `performance-engine.md` | 表演随剧情变化是合法的，不用锁死表情 |

### 顺序

```
第3站 建资产（长相、空间结构）
   ↓
第4站 前：建连续性锁定表（状态基线）
   ↓
第4站 每镜：Base Lock + Shot Delta → 九层单帧
   ↓
第5站：承接上文 + 表演变化
```

## 六、最常见的六种崩

| 崩法 | 症状 | 预防 |
|---|---|---|
| **脸漂移** | 越到后面越对称、越像塑料 | 身份只从资产取一次；不对同一张设定图反复迭代 |
| **服装复位** | 上一镜湿了，下一镜干了 | 服装状态进 Shot Delta，逐镜追 |
| **道具换手** | 信从右手跑到左手，没人发现 | 道具归属单列一行 |
| **拓扑翻转** | 门跑到另一边，窗外景变了 | 地点拓扑锁左右与远近 |
| **光源乱跑** | 每一镜的光都从"最好看"的方向来 | 光源位置进 Base Lock |
| **时间倒流** | 落日越拍越高、雨越下越小 | 时间推进单列，只许单向 |

## 七、交付格式

多镜项目建议同时给出：

1. **锁定表**（八个字段，只填相关的）
2. **镜头清单**（镜号 / 时长 / 景别 / 一句话内容 / 关键状态变化）
3. **逐镜 Shot Delta**
4. 各镜提示词

镜头多的时候，**先出锁定表和镜头清单**，让用户确认，再分批出提示词——一次性全出会质量下降。

---

## 八、自检

- [ ] 锁定表只填了真正需要锁的，没有把整段剧本抄进去
- [ ] 每个人物只有一份身份描述，没有每镜重写
- [ ] 服装 / 妆容 / 伤口 / 湿度的状态按时间单向推进
- [ ] 道具的归属和位置每一次移动都有交代
- [ ] 地点拓扑锁了左右与远近
- [ ] 光源位置在 Base Lock 里，没有每镜重布
- [ ] Shot Delta 只写变化，没有重复 Base Lock
- [ ] 没有为了"更好看"而悄悄改掉 Base Lock
- [ ] 反转与倒叙的知情状态单独标了，没有把后面才揭晓的信息漏进前面的镜头
